## 一、底层网络线路与物理架构篇

### Q1: IPLC、IEPL 和普通公网 BGP 中转有什么本质物理区别？
**A:** 它们的核心区别在于**流量是否经过物理层面的国家防火墙（GFW）以及是否拥有专属独立物理光缆**：
1. **IPLC（International Private Leased Circuit，国际私有租用线路）**：
   - 纯商业点对点内网专线。数据从国内入口机房进入后，通过物理拉通的海底光缆或陆地光缆直接传输到境外落地机房，**完全不经过公网，不经过 GFW 审查，几乎不受敏感时期封锁影响**。延迟固定，零抖动，但成本最为高昂。
2. **IEPL（International Ethernet Private Line，国际以太网专线）**：
   - 基于以太网架构的新一代二层物理专线（如本站主力推介的 [光速云 IEPL 专线](/p/guangsu-cloud-review/)）。在物理特性上与 IPLC 同样走端到端隔离专线，**同样不经公网骨干出口与 GFW**，但兼容性更好、带宽扩展更灵活、丢包率极低（实测 0.0%），是当前综合体验与性价比最高的顶级线路。
3. **普通公网 BGP 中转 / 隧道（Relay / Tunnel）**：
   - 国内入口采用优质多线 BGP 机房，将用户请求加密包装后，通过普通公网国际出口发送到境外服务器。平时速度快，但在国际出口晚高峰拥堵或特殊网络敏感期，仍可能面临丢包和 QOS 限速。
4. **普通公网直连（Direct）**：
   - 本地设备直接连接境外 VPS，完全暴露在公网骨干网络上。极易受晚高峰拥堵影响，丢包率往往超过 30%，目前主流高品质机场已极少采用。

### Q2: 为什么晚高峰（20:00 - 23:00）普通节点卡成 PPT，而 IEPL 专线却能满速跑？
**A:** 根源在于**“公网国际出口总带宽饱和”与“独立物理专线资源隔离”的物理差异**。
- 每天晚上 8 点到 11 点，数以亿计的网民同时访问国际互联网，导致电信（163）、联通（169）、移动（CMI）的公网国际出口骨干网路由队列瞬间爆满，触发运营商的 **QoS 丢包策略**（优先丢弃大流量和未知 UDP/TCP 包）。
- 而 IEPL / IPLC 专线是服务商直接向电信联通租用的**端到端物理私有通道**，其带宽资源与其他网民的公网流量在物理层完全隔离开，不受骨干网拥塞影响，因此能实现 24 小时恒定低延迟与零丢包。

### Q3: 什么是入口、出口、落地节点与隧道传输？
**A:**
- **入口（Ingress）**：您的电脑或手机第一步连接的服务器。通常位于国内各大城市（如广州、深圳、上海、徐州、北京）的优质机房。
- **传输隧道（Transit Tunnel）**：入口服务器与境外出口服务器之间建立的专用加密管道。
- **出口/落地（Egress / Landing）**：真正去向目标网站（如 Google、YouTube、Netflix、OpenAI）发起 HTTP 请求的境外服务器（如香港、日本、新加坡、美国机房）。落地节点的 IP 地址决定了您最终呈现给网站的地理位置与流媒体解锁能力。

## 二、现代代理协议与加密技术篇

### Q4: 常见的 Shadowsocks、VMess、VLESS、Trojan、Hysteria2 协议有何优劣？
**A:**
```
【主流出海代理协议演进路线】
Shadowsocks (经典简单但特征明显)
     |
  VMess (V2Ray核心，加密强但协议头开销大)
     |
  VLESS + REALITY (轻量去特征，伪装成正常主流TLS流量，抗封锁极佳)
     |
  Hysteria 2 / TUIC (基于QUIC/UDP，突破恶劣网络丢包，单线程吞吐之王)
```

| 协议名称 | 传输层基础 | 核心优点 | 核心缺点 | 推荐应用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **Shadowsocks (SS)** | TCP / UDP | 轻量无状态，内存与 CPU 消耗极低 | 协议特征已被深入研究，在纯公网直连易被精准识别 | 专线内网传输、低功耗软路由 |
| **VMess** | TCP / mKCP / WS | 支持复杂分流架构，兼容客户端最广 | 协议时间戳校验严格，头部加密计算开销较大 | 早期通用机场常用，正逐步被替代 |
| **VLESS (REALITY)** | TCP + TLS | 零冗余认证、完美借用正规大厂真实证书，抗主动探测能力全网顶尖 | 需要服务端规范配置 SNI | 2026年直连与中转主流首选 |
| **Hysteria 2 (歇斯底里)** | UDP (基于 QUIC) | 自研暴力拥塞控制，在 30% 丢包的恶劣弱网下仍能拉满千兆 | 部分运营商（如某些省份移动）对未知 UDP 强行 QoS 限速 | 晚高峰弱网抢带宽、长距离跨洋连接 |
| **Trojan** | TCP + TLS | 将流量完美伪装成最标准的 HTTPS 网站流量 | 遇到单边延迟高的链路吞吐提升不如 UDP 协议 | 稳定性与伪装度要求极高的场景 |

### Q5: 为什么 2026 年新机场和客户端全面倾向于 VLESS 与 Hysteria 2？
**A:** 随着深度包检测（DPI）技术的迭代，传统的固定特征混淆很容易被机器学习模型识别。**VLESS 配合 REALITY 伪装技术**去除了所有多余的协议头特征，在审查系统看来与正常的浏览器访问微软或苹果服务器毫无二致；而 **Hysteria 2** 彻底打破了传统 TCP 协议“一有丢包就主动减半发送速率”的保守机制，能够利用 UDP 动态多路复用，在恶劣网络中提供传统协议 3~5 倍的实际下行带宽。

## 三、AI 生产力与流媒体原生解锁风控篇

### Q6: 为什么我的节点能看 4K YouTube，但在访问 ChatGPT 或 Claude 时却提示 Access Denied 或 Sorry, you have been blocked？
**A:** 视频网站与 AI 平台对 IP 的风控要求完全不在一个量级：
1. **YouTube** 几乎不审查出口 IP 的来源属性，只要带宽足够即可流畅播放；
2. **OpenAI (ChatGPT) 与 Anthropic (Claude)** 部署了全球最严苛的反欺诈风控系统（接入了 Cloudflare Turnstile、IP2Location、MaxMind 商业数据库）。
- **拦截核心逻辑**：如果出口 IP 被识别为 **“机房托管 IP (Data Center / Hosting)”**，或者该 IP 段近期有大量并发请求被滥用，OpenAI 会对整个 IP 段下发软阻断或直接封禁；
- **解决之道**：必须使用具备 **原生住宅属性（Residential / ISP）** 的优质双 ISP 落地节点。

### Q7: 什么是“原生双 ISP 住宅 IP”？为什么它在 2026 年如此珍贵？
**A:**
- **单 ISP / 机房 IP**：网络服务提供商（ASN）直接标注为 Amazon AWS、Google Cloud、DigitalOcean 等商业云厂商机房。任何网站的风控算法都能瞬间识别其为虚拟机器人或代理服务器。
- **原生双 ISP IP**：IP 地址由海外当地正规民用宽带运营商（如香港 HKT/HGC、美国 AT&T/Verizon）直接分配，在网络数据库中的属性为真实家庭住址宽带。
- **优势**：无论是登录 **ChatGPT 4o、Claude 3.5 Sonnet、TikTok 国际版创作者后台，还是 Steam 跨区购买**，均会被判定为当地真实自然人居民，**完全规避频繁弹验证码或连带封号的风险**。

## 四、客户端故障排障与系统疑难杂症篇

### Q8: 关掉代理客户端后，电脑连百度、微信都打不开了，必须重新打开客户端才能上网，如何解决？
**A:** 这是最常见但也最令新手恐慌的**“系统代理注册表死锁残留”**现象。
- **产生原因**：当客户端（如 Clash Verge 或 v2rayN）正在运行时，它会在 Windows 系统中将系统的代理服务器设置为 `127.0.0.1:7897`。如果客户端遇到**崩溃、强制任务管理器结束、或电脑在未关闭代理前直接睡眠/强制关机**，系统设置里的这个回环代理开关未能被正常还原关闭。当客户端不运行时，系统依然试图将所有流量转发给不存在的本地端口，导致彻底断网。
- **一秒恢复实战三步法**：
  1. 按键盘快捷键 `Win + i` 打开 Windows「设置」；
  2. 点击「网络和 Internet」-> 左侧或右侧选择「代理」；
  3. 找到「手动设置代理」，将**「使用代理服务器」开关彻底关闭**，并点击保存。此时网络即可瞬间恢复正常！

```
【Windows 代理设置修复路径】
[设置] -> [网络和 Internet] -> [代理] -> [手动设置代理: 使用代理服务器 -> 切换为: 关]
```

### Q9: 为什么开启了代理后，网页能正常出海，但 Telegram、Discord、Spotify、Steam 依然提示无网络？
**A:** 普通客户端默认开启的是**「系统代理 (System Proxy)」模式**。
- 系统代理仅对遵循系统标准网络调用的现代浏览器有效；
- 像 Discord、Telegram 客户端、Steam 社区与绝大部分外服竞技游戏，使用的是底层的原生 Socket 或虚拟驱动，它们会完全绕过系统代理直接连网，导致被阻断；
- **终极解决方案**：在 [Clash Verge Rev](/p/proxy-clients-complete-guide/) 中安装系统服务并开启 **「TUN 虚拟网卡模式 (TUN Mode)」**。TUN 模式会在系统底层创建一张虚拟网卡，将整机所有的 TCP/UDP 数据包无缝重定向给代理内核分流，实现真正的全局接管。

### Q10: 什么是 DNS 泄漏？什么是 Fake-IP 模式？
**A:**
- **DNS 泄漏（DNS Leak）**：即使您的网页数据走的是加密代理通道，但电脑在解析域名时，依然向本地宽带运营商（如当地电信/移动的 114.114.114.114）发起了明文的 DNS 查询。运营商可以清晰知道您正在访问哪些海外域名，导致隐私泄露。
- **Fake-IP 模式**：Mihomo / Clash 内核的高级特性。当本地软件发起域名解析时，客户端不向远程发送查询，而是立即给本地返回一个保留的假 IP（如 `198.18.0.x`），并由代理客户端在远端服务器上真正发起安全解析。这不仅彻底杜绝了 DNS 泄漏，还将域名连接建立时间缩短至接近 0ms。

### Q12: 机场支持一人多设备同时使用吗？能否借给朋友合租？
**A:**
- **多设备支持**：绝大多数正规商业机场均支持同一个账号在用户的多台设备上同时在线（例如手机、笔记本、iPad 同时连接，通常上限为 3~5 台设备）；
- **合租与共享禁忌**：切勿将自己的订阅链接公开发布在社交网络或借给多人使用。正规机场后台均部署了**并发 IP 异常熔断机制**。如果系统检测到该订阅在短时间内于相距数千公里的不同省份 IP 同时发起连接，会被判定为账号被盗或恶意倒卖，触发自动化封禁并不予退款。
